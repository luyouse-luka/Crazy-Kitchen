# pipeline · AI 内容生产管线

离线 Node，与引擎完全无关。产出顾客卡 JSON → 校验 → 验收通过才拷进 `game/assets/resources/`。

> **AI 是内容生产管线，不是运行时服务。** 即使不计成本，运行时调用这条路在微信小游戏上
> 也走不通：`api.anthropic.com` 进不了 request 白名单、API key 不能进包体（可解包）。
> 预生成的 JSON 是静态资源，运行时零依赖、零故障面。

## C2 要做什么

```
代码抽维度 → 组装 prompt → Opus 5 + Batch API(5折) → schema 校验 → validateOrderSpec 复校 → 人工读 200 张打分
```

200 张约 **$2.5**。跑批可放夜里。

**两道校验缺一不可：**

1. `customer.schema.json` —— 拦词表外取值、超长台词、多余/缺失字段
2. `game/assets/logic/order.ts` 的 `validateOrderSpec()` —— 拦 **required 与 banned 相交**

第二道不能省：JSON Schema 表达不了跨字段约束，相交的卡它照单全收，
而那种卡进了包体，玩家会遇到一单永远做不出来。`__tests__/schema.test.ts` 里
有一条测试专门把这个能力边界钉住。

## 生成时的铁律

> `lines.order` 是 `order` 字段的人话包装。它可以用任何离谱的说法描述这些食材和火候，
> **但不能引入机制层不存在的要求。玩家只要满足了机制层，判定就必须是成功。**

要在 prompt 里拒绝的反例：

| 违规台词 | 为什么违规 |
|---|---|
| 「再给我一杯血腥玛丽」 | 引入了词表外的物品，玩家做不出来 |
| 「装盘时摆成五芒星」 | 引入了机制层没有的摆盘维度 |
| 「你猜我要什么」「随便，看着办」 | 需求不可知，玩家无法完成 |

另外一条硬约束（判据 3 的修法）：**执念必须体现为具体的食材增删或火候要求**，
否则会生成一堆「身份很搞笑、订单却是普通汉堡」的卡 —— 玩家正忙着跑冰箱，
只会瞥一眼 `order` 那句，笑点没长在那句上就等于不存在。

## 验收判据（M0 的 go/no-go 闸门）

生成 200 张，**不写游戏，纯文本读一遍**：

| 判据 | 线 | 不过怎么办 |
|---|---|---|
| 截图率 ≥ **15%**（≥30 张想截图发朋友） | <10% 方向不成立 | 厨房和动画救不了不好笑的卡，只会更贵 |
| 重复感衰减点 ≥ **50 张** | 早于 50 张 | 维度池太小或 prompt 引导太强，先扩池再重跑 |
| 机制耦合率 ≥ **40%** | — | prompt 里加硬约束：执念必须落到食材或火候上 |

**三条都过，才谈得上做厨房。** 详见 `docs/ai-customer-v1.md` §7 与 `ROADMAP.md` M0 线 C。

## 扩池

往 `dimensions.json` 的数组里加值即可，不改 schema、不改脚本。
