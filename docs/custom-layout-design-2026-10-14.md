# 自定义厨房布局设计草案

2026-10-15 整合补充（覆盖下方旧默认坐标）：用户要求冰箱靠近仓库、常用工位不放角落。新默认采用北侧备餐线：冰箱 (3.5,-2.5)、烤炉 (.5,-2.5)、制作台 (-1.5,-2.5)，三者操作面朝中央；取盘架 (-3.5,0) 在西侧中段。炸锅移至 (-3.5,-1.5)，饮料底柜 (2,-2.5)，洗区与灭火器保留。制作台占地改为 2×1 米，移除其占用位置原有填充柜。默认与恢复默认、旧档迁移共用此版。

日期：2026-10-14。用户已确认：工位可以自由移动和旋转，建筑边界固定。本文定义下一批实现范围；月度费用、破产与奖励单独作为后期建议，不在本批接入。

2026-10-15 补充：用户要求默认冰箱与盘子进一步离开角落。默认冰箱改为左侧中段 `(-3.5, 0)`，取盘架紧邻 `(-3.5, 1)`，制作台向后顺移至 `(-3.5, -1.5)`。中央空地继续保留；编辑器“恢复默认”和旧档迁移均采用此版默认位置。其他默认工位沿用现有 `tools/scene-spec.ts`。

## 玩家操作

沿用前台的休息日装修入口，新增“调整厨房布局”。编辑期间顾客、厨房计时和角色移动冻结；营业中不能编辑。

1. 点选工位，显示名称、实际占地和可拖动的轮廓。
2. 拖到新位置，落点吸附到 0.5m 地面格子。默认布局的精确坐标保持原样，只有玩家实际拖动的工位执行吸附。拖动过程中不改变已经保存的配置。
3. 点“旋转”切换 0 / 90 / 180 / 270 度；碰撞范围随实际宽深交换。
4. 合法位置显示绿色轮廓，越界、重叠或堵路显示红色及具体原因。
5. “撤销”恢复上一步，保留最近 20 步；“取消”恢复进入编辑前的布局。
6. “恢复默认”替换编辑草稿；仍需点“保存布局”才写入存档。“保存布局”通过全部检查后生效并退出编辑。

首次进入显示一次短提示。相机在编辑期间展示整个厨房；退出后恢复现有跟随镜头。顶部保留退出和保存按钮，底部只显示旋转、撤销和恢复默认，编辑画面不同时显示游戏摇杆、取放或丢弃键。

## 可调整与固定内容

| 内容 | 本批行为 |
| --- | --- |
| 冰箱、烤炉、制作台、取盘架 | 可移动、可旋转 |
| 洗碗台、晾盘架 | 可分别移动、可旋转；洗碗台的两段模型作为一个工位移动 |
| 已购炸锅、饮料机 | 可移动、可旋转；未购买时保留默认位置，购买后按保存配置显示 |
| 灭火器 | 可移动；保留原取放和灭火规则 |
| 房屋地板、墙、门、冷库边界 | 固定 |
| 前台柜台 | 建筑与顾客区边界固定 |
| 接单、出餐窗口和外卖交付点 | 建议沿固定前台横向调整位置，保留朝向顾客的服务方向 |
| 冷库货架与补货点、顾客座位 | 固定 |
| 墙地配色、既有装饰槽 | 沿用现有装修功能 |

厨房设备支持四档旋转；前台服务窗口建议仅横向移动，旋转按钮显示“面向顾客”，不把窗移进厨房让顾客穿越边界。旋转只改变摆位和操作面的朝向，不改变库存、锅位数量、加工时间、升级效果或设备拥有状态。布局调整免费；设备购买继续走现有商店。自定义布局允许改善跑腿效率，这是玩家决策的收益。

## 保存前检查

- 所有设备占地及角色接近区位于主厨房 / 洗区的现有可玩地板内，不能放到顾客区或冷库，也不能穿墙。
- 工位之间、与固定柜台之间不重叠。0.7m 角色直径和 0.7m 交互距离沿用现有值，不靠缩小人物碰撞让布局通过。
- 主通道与冷库门口保留 1.5m 净宽；出生点及主要通道必须与所有工位有效操作面连通。
- 工位必须有符合其操作面朝向的接近位置。烤炉、冰箱不能背对通道却仍隔墙取物。
- 接单、堂食出餐、外卖交付、洗碗、取盘、补货和灭火器仍可达。设备看得见但够不着的布局不能保存。
- 编辑器显示具体错误，例如“制作台堵住冷库门口”，避免只有一个红色框。
- 无法从原布局移动到新的安全站位时，退出编辑把角色放到已验证的出生点；这只发生在装修结束时，不在营业中移动角色。

当前 `tools/layout-navigation.ts` 的导航网格可用于离线默认布局验证；运行时只做保存和加载时的检查，不逐帧寻路。纯校验函数放在 `game/assets/logic/`，保持零 `cc` 依赖；工具脚本与游戏复用它。

默认布局继续守住原难度曲线。用户自定义布局只检查安全与可操作性，不强迫其完成率等同默认布局，也不自动变更客流来抵消玩家的布局收益。

## 数据与运行时同步

存档增加 `layout: { version: 1, stations: { <工位ID>: { x, z, quarterTurn } } }`；工位 ID 使用稳定的玩法标识，不使用 Cocos 节点 UUID。字段缺失、非有限数值、不合法朝向或未知设备 ID 不能直接应用。

旧 v1 / v2 存档迁移到新格式，保持天数、星级、金币、设备购买和装饰。无布局记录的旧档使用新的默认布局；损坏布局单独回退到默认，不清空其他进度。保存布局与现有进度一次写入，同一次编辑不会单独落一半设备位置。

加载 / 保存生效时，从同一份布局更新：工位逻辑坐标、碰撞盒、模型位置和旋转、交互范围、锅具、火焰 / 水流等效果锚点、贴地阴影、环形进度及指示位置。不得只移动模型、留下空气墙或旧特效。

`StationView.toStation` 和 `readBoxes` 目前按世界缩放读取轴对齐盒；新增旋转后需使用共享宽深规格计算正确的盒子。`WorkstationEffects` 目前在构造时缓存锚点，应用新布局后重新创建效果对象与锅具，并释放旧资源。现有接触阴影是全场烘焙坐标，需改为根据当前工位占地一次生成的合并阴影，位置随布局应用更新。

设备组内所有子模型一起移动；柜台和附属道具不能各存一个互相矛盾的位置。固定建筑及前台柜台只作为校验障碍。前台服务点独立保存其横向位置，并同步电脑、出餐提示、交付点和顾客排队 / 取餐锚点，不拖动整排柜台。

## 验收

纯逻辑检查覆盖合法摆位、90 度宽深交换、设备重叠、越界、封门、不可达操作面、损坏布局回退及旧档迁移。负向检查先用可达默认布局作为活性锚点。

浏览器通过真实点选、拖动和按钮操作完成：移动冰箱、旋转制作台、拒绝堵门布局、取消、撤销、恢复默认、保存及刷新读回；保存后的厨房以摇杆完成取料、煎肉、制作、送餐、洗盘和补货。检查火焰 / 水流 / 锅具与模型一致、旧位置没有碰撞或阴影残留。

4:3、16:9 与长屏分别检查工具栏和设备可选范围，防止编辑 UI 遮住设备。微信工程重新构建并核对主包、分包和资源加载；最终拖动和多指触控由手机试玩签收。

## 后期经营费用建议

当前 `Progress.day` 是解锁关卡，重玩同一天不推进；休息也不算天数。月度账单需要独立的游戏内经营日期，不能直接使用关卡天数。建议按游戏内 30 天结算，不在玩家离线时按真实日历累加欠费。

| 费用 | 建议规则 |
| --- | --- |
| 房租 | 固定月费，店面升级后变化；月初可查看预计账单 |
| 水电 | 根据烤炉、炸锅、饮料机工作时间和洗盘用量累计，设备升级可降低消耗 |
| 商税 | 与净盈利挂钩，亏损时不再按盈利征收；具体比例由实际收入分布标定 |
| 安全税 | 可表现为安全维护费；按时维护、无事故可减免，明确事故另记罚款 |

账单应提前提醒，并给出当月收入、已支出、预计费用和预计结余。初期先让玩家学会营业，再逐项开放经营负担；不要同时叠加所有费用，抵消前面已经承诺的新手降难度。

先独立记录账目，再标定费用，最后接入欠款和破产。当前存档金币最低为 0，欠款需用单独的非负 `debt` 字段；不能把负金币写回当前格式后被读档静默抹掉。

## 破产惩罚与恢复建议

推荐“经营重整”而非永久清档：保留菜谱、已解锁进度和基础厨房，暂时停止购买新设备与扩大店面，允许出售非核心装饰偿债，并提供基础救济订单恢复现金流。

短期惩罚可以是优惠订单收益降低、扩建资格暂停，或退出一个月度评奖。逾期原因和偿债目标必须可见，偿还后解除限制。新手的第一次资不抵债提供一次救助和重新规划账单的机会。

不建议把破产惩罚做成移速变慢、顾客耐心更短或拆掉必需烤炉；这些会继续降低挣钱能力，使玩家更难恢复。债务也不应无限滚高到无法通过正常营业偿还。

## 对应奖励建议

- 按时缴费：获得下月房租折扣或一次装修优惠。
- 无安全事故、维护及时：减免或返还部分安全维护费。
- 持续高评分与健康现金流：获得特殊装饰、招牌或店面主题，附少量经营奖励。
- 完成重整：给予一次小额设备优惠，奖励恢复经营，不让反复故意破产成为挣钱策略。

奖励先保留为机制建议，不填未经试玩标定的价格和比例。自定义工位是当前下一批；月度费用、破产和奖励不随布局保存立即生效。
