AI 看不见你的编辑器

凡是「节点在场景里叫什么、挂在哪一层」这类信息，要么按命名约定，要么你说。 约定：工位 Station_Fridge · 角色 Prefab_Chef · UI UI_Joystick · 挂载点 Anchor_Hand。 对不上的时候是你改名字，不是 AI 改代码 —— 代码有测试兜底，场景没有。

现在就做 · 线 A 详细步骤

跑通空项目的完整发布链路

先跑通链路，再写一行游戏代码。这条链路卡住，后面全白搭。 A2 → A4 有严格先后，A5–A8 可以穿插。

A2

把工程接到本地

有个坑

clone 到 Unison 同步范围之外，从此这个项目只认 git：

git clone https://github.com/luyouse-luka/Crazy-Kitchen.git D:\dev\Crazy-Kitchen

首次会弹浏览器登录 luyouse-luka。放在 D:\dev\ 之后， Unison 碰不到你的工作副本，那两份旧的同步副本备份完就可以删。

⚠ Cocos 新建项目会和已有的 game/ 撞车

仓库里已经有 game/assets/logic/（20 个文件），但没有 Cocos 工程文件。 而 Cocos Dashboard 新建项目要求目标目录是空的 —— 直接建会被拒。

做法是先把 logic 挪开，建完再挪回来：

cd D:\dev\Crazy-Kitchen
ren game game_tmp

# → 这时用 Cocos Dashboard 新建 3D 空项目，路径选
#   D:\dev\Crazy-Kitchen\game
# → 建完先关掉编辑器，再执行下面两行

move game_tmp\assets\logic game\assets\logic
rmdir /s game_tmp

然后用编辑器打开（不是新建）D:\dev\Crazy-Kitchen\game， 它会为 assets/logic/ 下每个 .ts 生成 .meta。 这些 .meta 必须 commit —— 它存 uuid 映射， 删了场景里拖好的引用会全部变空。

判据 编辑器资源管理器里能看到 assets/logic，且 git status 里出现一批新的 .meta。
A3

装 Cocos Creator 3.8

从 Cocos Dashboard 安装。版本必须是 3.8.x —— 方案里所有 API、 构建面板选项、目录结构都是按 3.8 写的，3.9 / 2.x 对不上。

判据 Dashboard 的编辑器列表里 3.8.x 显示已安装。
A4

建项目 → 构建 → 真机扫码

本周最高优先级

用 3D 空模板。建完第一件事设分辨率与朝向： 项目 → 项目设置 → 项目数据 里设计分辨率填 1280 × 720； 朝向在构建微信小游戏面板里另有一个「设备方向 / Orientation」， 两处都要是横屏 Landscape。

（菜单位置以你实际装的 3.8.x 为准，如果对不上按「设计分辨率」「Orientation」两个关键词找。）

然后跑完整条链路，一环都不能省：

  1. 编辑器 项目 → 构建发布 → 平台选微信小游戏 → 构建
  2. 用微信开发者工具打开构建产物 → 能跑
  3. 开发者工具里点预览 → 手机扫码 → 真机上能跑

卡 2–3 天是正常的。第一次做证书 / AppID / 构建配置几乎人人卡， 方案里提前写明了这一点，不是你不行。 卡超过两个晚上就停下来问 AI —— 这是它在这个项目里最能帮上忙的地方。

判据 手机上看到 Cocos 空场景。开发者工具里跑起来不算数。
A5

记下包体真实数字

构建产物里找 cocos-js 的大小，以及主包总大小，两个数都记下来。

方案 §2.4 现在用的 2.2–2.8MB 是从 2D 项目外推的估值， 要用你这个真数替换。这个数定了后面所有资源预算： 分包策略、字体子集大小、顾客卡首包带几张，全从它推。

判据 两个数字写进 ROADMAP，估值那行划掉。总量红线 16MB / 安全线 15MB。
A6

AppID + iOS 高性能模式

  • 微信公众平台注册小游戏 AppID（个人主体，免费）
  • 开通高性能模式：能力地图 → 研发能力 → 生产提效包， 然后 game.json 加 iOSHighPerformance: true

免费、无 DAU 门槛、无主体限制。官方压测（12000 条鱼）： iPhone 11 Pro Max 从 10–15 帧提到 48–50 帧。要求 iOS 14+ / 微信 8.0.18+。

连带一个必须现在定死的决定：纹理格式只能用 ASTC。 高性能模式不支持 ETC / PVRTC。这条越早定越好 —— 它反过来约束整条美术管线，等 M6 才发现要全部重导会很惨。

A7

验证分层能不能落地

不过就要改架构

整个 logic/ 分层架构成不成立，全看这一条。做法：

  1. 在 assets/scripts/ 建一个组件，import { judge } from '../logic/order'
  2. 编辑器不报错
  3. 构建一次，在构建产物里搜得到 logic 的代码

第 3 条是关键 —— 编辑器不报错但没进产物，真机上就是空白报错。

不过的退路：把 logic/ 移出 assets/， 用 tsconfig outFile 编译成单个 js 吐回 assets。 代价是多一个构建步骤 + 调试行号对不上，但架构不用改。

判据 构建产物里 grep 得到 logic 里的函数名。
A8

盘一下手上有哪些测试机

列出安卓型号、有没有旧 iPhone（2G / 3G RAM 那种）。

现在知道还来得及借。微信开发者工具的 iOS 模拟 测不出内存被系统杀 —— 这是最可能真机闪退的地方， 等 M6 才发现没机器测就晚了。真没有就得接受「首发只保安卓」，那也要提前决定。

斜 45° 的头号手感坑

把摇杆的 (x, y) 直接当世界的 (x, z)， 玩家往上推、角色却斜着走 —— 因为相机绕 Y 轴转了 45°。 正解是先把输入向量按相机 yaw 旋转再喂给移动， vec2.rotateY() 已经写好并测过了。 这行代码写不写对，决定这个游戏手感对不对，比后面所有美术都重要。

GATE · 最容易卡死的地方
游戏名定死 → 提交软著

软著审查约 30 工作日，含来回补正现实要 6–12 周。 而软著证书上的名称必须与最终上架名称完全一致 —— 定错就要重新申请，直接推迟上线两三个月。

链条是：定名 → 提软著 → 等 6–12 周 → 期间继续做 M3/M4/M5/M6 → 下证即可提审。 排在 M2 而不是更晚，是因为软著材料要源代码 + 说明书截图， M2 的垂直切片刚好够，而 M3 时 UI 还在动、截图要重做。

M3 验收 · 分层架构的红利

除了主观的「连玩 5 局差评率 > 0」，还有一条客观判据： 模拟器预测 vs 真人实测的偏差。 模拟器说「同时 3 单开始崩」，你如果 2 单就崩，说明操作摩擦比预期大一倍 —— 这时该改的是操作和 UI，不是难度数值。

这把「手感不好」这种主观抱怨变成了一个可量化的差值。没有 sim.ts 就只能靠「我觉得有点难」来调参。

日常怎么跑

每次开工 · 收工的固定动作

# 开工（30 秒，别跳过）
git pull
npx vitest run          # 逻辑层没坏，才值得开编辑器
# → 然后再启动 Cocos Creator

# 收工
git add -A && git commit -m "..." && git push

vitest 那一步是为了避免最糟的情况：开了编辑器调半天， 最后发现是 AI 推的逻辑改动坏了。30 秒换掉半小时。

冲突处理

  • 场景 / prefab 冲突不 merge。谁的版本新用谁的，另一方重做那次改动 —— uuid 太多，手动 merge 几乎不可能对
  • .ts 冲突正常 merge，有测试兜底
  • .meta 必须进仓库
  • library/ temp/ build/ 已在 .gitignore 里

接口契约

  • AI 改 logic/ 公开导出，同步改 API.md，commit 打 [API] 前缀
  • 你 pull 后 Cocos 编译报错，第一件事看 git log --oneline | grep API
  • 组件里只允许调 API.md 上列出的东西 —— 想要新方法就说，别自己在组件里写一份

每周至少产出一个能截图或录屏的变化

哪怕只是「角色手上多了个方块代表汉堡」。 业余项目最大的杀手不是技术难题，是失去节奏后再也回不来。 看得见的进展是燃料 —— 连续两周没有可视变化，说明当前任务拆得太粗，要拆小。

规则

闸门与取舍

带着下面任何一条，不许进入下一个里程碑

  • npx vitest run 有红灯
  • 核心路径上留着 TODO 或写死的假数据
  • 真机上跑不起来（开发者工具跑得起来不算数）
  • 本里程碑的验收判据有一条没过
  • 包体数字没记（M2 起每个里程碑收尾都要记一次）

业余项目最常见的死法是「M2 还剩三个 bug，但我想做 M3 了」，然后债务滚到收不了场。

卡住了可以砍

  • 美术（几何体能一路撑到 M6）
  • 音效（M4 再补）
  • 动画打磨、粒子特效
  • 外卖、卫生检查等混乱源（挑两个做也成立）

不能砍

  • 发布链路（M0 卡住就全盘卡住）
  • 核心循环（接单 → 做 → 交付 → 反馈）
  • 存档（有天数推进就必须有）
  • 软著（时间线最长，砍了就上不了线）

卡在某个技术点超过两个晚上就停下来问 AI，别自己硬啃 —— 这是它在这个项目里最能帮上忙的地方。
