# M2 场景搭建指南 · 斜 45° 轻 3D

> 面向 **ly 在 Cocos Creator 3.8.8 编辑器里的操作**。
> 代码侧（`logic/` 与 `scripts/`）不在这份文档里，接口看 `game/assets/logic/API.md`。
>
> **这份文档的定位**：M2 的目标是「30 秒能玩完的最丑版本」。
> 下面每一条的取舍标准都是**「能不能玩」，不是「好不好看」**。
> 凡是写着「M2 不做」的，都不是忘了，是刻意推迟——理由都写在旁边。

## 0. 三条红线：越过去要付真金白银

这三条不是风格建议。每一条都对应 A5 已经实测出来的包体数字，越过去就白费。

| # | 红线 | 越界的代价 | 判据（构建后自己能查） |
|---|---|---|---|
| 1 | **任何节点都不许加物理组件**（`BoxCollider` / `RigidBody` / `SphereCollider` …） | 物理模块进包：ammo wasm 约 1.2 MB + js 约 0.7 MB。A5 已经确认物理被裁干净了，加一个组件就全回来 | 构建产物里 `grep -c "b2World\|PhysicsSystem\|ammo\|cannon"` 应为 **0** |
| 2 | **不开实时阴影**（方向光的 Shadow 不勾、场景 Shadows 不启用） | 移动端实时阴影是最贵的单项之一，而斜 45° 固定相机根本不需要它 | 见下面 §5 的 Blob Shadow |
| 3 | **不给 Skybox 指定 cubemap 贴图 / 不勾 HDR** | 850 KB。A5 那次它自己消失了，是因为新工程没引用；手动指定就会回来 | `pnpm size` 的 assets 那一栏应保持在 400 KB 上下 |

> ⚠ 第 1 条最容易犯——因为 Cocos 的教程几乎全在教你加 Collider。
> **这个项目的碰撞全部在 `logic/collision.ts` 里手写**，编辑器里的方块只是「看得见的形状」，
> 不参与任何判定。你在编辑器里加的 Collider 不会让游戏更对，只会让包更大。

**M2 还不做的**（不是遗漏）：后处理（Bloom / FXAA）· 光照烘焙（lightmap）· 任何贴图 ·
任何模型文件（`.fbx` / `.gltf`）· 音效 · 粒子。

## 1. 坐标系与单位：先把这个对齐，后面全省事

| 约定 | 值 |
|---|---|
| **1 世界单位 = 1 米** | 编辑器里 scale=1 的 Cube 就是 1 米见方 |
| **玩法平面是 XZ** | 角色只在 X 和 Z 上移动，**Y 恒定**。无跳跃、无斜坡、无楼层 |
| **地板在 y = 0** | 角色的 `position.y` = 半身高（固定值），不参与逻辑 |
| **厨房原点在地板中心** | `Kitchen` 节点放 `(0, 0, 0)`，所有工位坐标相对它 |
| **`logic/` 里的坐标是 `{x, z}`** | 没有 `Vec3`。组件负责在 `Vec3` 与 `{x,z}` 之间转，`logic/` 一侧永远只有两个分量 |

**按 1 米格子规划厨房，工位坐标全用整数或 0.5 的倍数。**
理由不是洁癖：我写单测时要手算「角色站在 (2, 3) 够不够得着灶台」，
坐标是 `2.37` 还是 `2` 决定了这个测试好不好写、将来出 bug 好不好查。

## 2. 场景层级：照这棵树建

命名严格按 ROADMAP §6.2。**我看不见你的编辑器**，代码里的 `find()` 全按这套名字写，
对不上的时候是改名字不是改代码——代码有测试兜底，场景没有。

```
Scene
├── Main Camera            正交 · 斜 45° · 建好就锁住别再动
├── Main Light             DirectionalLight · Shadow 不勾
│
├── Kitchen                静态场景根（将来整块烘焙/合并 mesh 就靠它成一整块）
│   ├── Floor              地板（Plane 或压扁的 Cube）
│   ├── Wall_N             北墙
│   ├── Wall_W             西墙
│   ├── Station_Fridge     ← 冰箱
│   ├── Station_Grill      ← 烤炉
│   ├── Station_Assembly   ← 组装台
│   └── Station_Serve      ← 出餐口
│
├── Actors                 会动的东西都在这层
│   ├── Player
│   │   ├── Body           胶囊
│   │   ├── Head           球
│   │   ├── Anchor_Hand    空节点 · 头顶持有物的挂点（§6.2 的 Anchor_ 约定）
│   │   └── Shadow         贴地椭圆片
│   └── Customers          空节点 · 运行时往里生成，编辑器里留空
│
└── Canvas                 UI（2D）
    ├── UI_Joystick        摇杆的视觉（左半屏）
    ├── UI_ActionButton    动作键（右半屏）
    └── UI_HUD             订单/金币/计时
```

**为什么静态和动态要分两棵子树**：`Kitchen` 底下的东西这辈子都不动，
将来可以整块合并成一个 mesh、烘一张 lightmap；`Actors` 底下每帧都在变。
现在分好，M3 做优化时是拖一个节点的事；现在混在一起，那时候要一个个挑。

> ⚠ **只有两面墙**（北 + 西），不是四面。斜 45° 相机从东南方向往下看，
> 南墙和东墙永远背对相机——建了也看不见，纯浪费。这是 §2.3「白拿的东西」里那条「模型背面可直接删面」的最简版。

## 3. 相机：斜 45° 怎么配

### 用正交（Ortho），不用透视

| | 正交 | 透视 |
|---|---|---|
| 远近物体大小 | 一样 | 近大远小 |
| 摇杆方向映射 | **屏幕方向 ↔ 世界方向恒定** | 随位置微变 |
| 「一眼看全厨房」 | 调一个 `Ortho Height` 就够 | 要同时调 FOV 和距离 |

正交是这类游戏的默认答案，也让 `input.ts` 里那套 camera-relative 映射**在全屏任何位置都成立**。

### 配置步骤（按顺序做，别跳）

1. 选中 `Main Camera` → Inspector 的 `Camera` 组件 → **`Projection` 改成 `ORTHO`**
2. **`Rotation` 先填 `(-35, 45, 0)`** ——
   - `-35` 是俯视角（负值往下看）。数学上的等距投影是 `-35.264°`（`arctan(1/√2)`），
     游戏里 30–45 都常见，先用 35
   - `45` 是绕 Y 的偏航，斜 45° 的「45」就是这个数
   - ⚠ **填完看场景视图确认是从右上方往下看**。如果方向不对，是欧拉角顺序的问题，
     把 45 改成 -45 或 135 试，**不要靠推理，看着调**
3. **`Position` 填 `(15, 15, 15)`** ——
   正交相机的位置**不影响能看到多大范围**，只影响看向哪里和裁剪。
   放远一点纯粹是为了别把厨房裁掉
4. **`Near` 填 `1`、`Far` 填 `100`** —— 相机在 (15,15,15) 距原点约 26 米，这个范围包得住
5. **`Ortho Height` 先填 `5`，然后调到「一眼看全厨房」** ——
   ⚠ 这个字段是**半高还是全高**，你填 5 看一眼就知道了：如果画面纵向覆盖约 10 米就是半高，
   约 5 米就是全高。**知道了把结论写进这一节**，省得下次再试
6. 调好之后 **在层级管理器里锁住 `Main Camera`**（节点右侧的小锁图标），
   防止后面拖别的节点时手滑把相机拖跑

### 相机是固定的，这是硬约束

ROADMAP §1「轻 3D 的精确落点」定死了：**固定角度、固定或轻微跟随位移，不可旋转、不可缩放。**
不是做不到，是一旦可旋转，`input.ts` 的 yaw 就变成每帧要读的动态值、
角色被家具挡住要写描边 shader、还要做相机碰撞——三样工作凭空长出来，
换来的是这个游戏根本不需要的自由度。

### 真机第一件事：验 yaw 的符号

`API.md` 里写了，这里再说一遍，因为它是**唯一一个我在服务器上验不了的输入层参数**：

> 上下左右各推一次摇杆，看角色往哪走。
> **前后反了** → 把传进 `stickToWorld` 的 yaw 取负。
> **左右反了** → 相机是往另一边转的，同样取负。
> 代码里锁死的是「先旋转再移动」这个结构，不是某个具体符号。

## 4. 光照：一盏灯，别开阴影

M2 只要能看出「这是个三维的盒子」就够了。

1. 场景里保留默认的 `Main Light`（`DirectionalLight`），**`Shadow Enabled` 不勾**
2. `Rotation` 大约 `(-50, -30, 0)`，让光从斜上方来 ——
   **别让光的方向和相机方向重合**，重合了每个面亮度一样，立体感全没了，
   看起来就像贴纸。这是最容易犯的一个，而且很难自己发现
3. `Color` 保持白、`Intensity` 默认。真要调等有了美术再说
4. **环境光**：点击层级管理器最顶上的场景节点 → Inspector → `Ambient` 分组 →
   `Sky Color` / `Ground Color` 用**纯色**。
   ⚠ **不要在 `Skybox` 里指定 cubemap 贴图，也不要勾 HDR**——红线 3，850 KB

阴影靠 §5 的贴片，不靠灯。

## 5. 材质：M2 阶段的做法

### 用 `builtin-standard`，纯色，零贴图

- 资源管理器右键 → **创建 → 材质** → Inspector 里 `Effect` 选 `builtin-standard`
- 只改 `Albedo`（基础色），**别挂任何贴图**
- 做完拖到节点 `MeshRenderer` 组件的 `Materials[0]` 上

**为什么是 standard 不是 unlit**：`unlit` 不受光照，六个面同色，方块看起来是平的。
`standard` 受光，能看出立体——M2 阶段这点立体感就是全部的「美术」。

**为什么不挂贴图**：纯色材质的包体几乎为零，一张 512×512 的 PNG 就是几十到几百 KB。
主包只剩约 1668 KB 给内容（§2.4a），M2 一张贴图都不该有。

### 建几个材质？

**别为 draw call 提前优化。** §2.2 算过：即使一行不优化也只有 90–125 个 draw call，
红线是 200，优化后能到 12–20。M2 阶段建 8–12 个材质完全没问题。

一个够用的配色（能一眼分清工位就行，不用好看）：

| 材质 | 用途 | 建议色 |
|---|---|---|
| `M_Floor` | 地板 | 浅灰 |
| `M_Wall` | 两面墙 | 更浅的灰（和地板要分得开） |
| `M_Fridge` | 冰箱 | 蓝 |
| `M_Grill` | 烤炉 | 深红 / 橙 |
| `M_Assembly` | 组装台 | 木黄 |
| `M_Serve` | 出餐口 | 绿 |
| `M_Player` | 玩家 | 亮色（在所有背景上都要跳出来） |
| `M_Shadow` | 贴地阴影 | 黑，半透明 |

> ⚠ **颜色不是随便挑的那一条**：玩家角色的颜色必须在**所有**工位颜色上都能一眼看见。
> 你在编辑器里看是清楚的，因为你知道它在哪；真机上手忙脚乱时找不到自己在哪，
> 是这类游戏最常见的早期反馈。

### 贴图什么时候才需要设压缩格式

现在不需要（没有贴图）。但**一旦开始导入贴图**，规矩是：
资源管理器选中图片 → Inspector 右上角选平台 → 压缩格式选 **ASTC**（A6 已定）。
默认的 PNG 会让包体和内存都翻倍，而 iOS 内存是这个项目最可能真机闪退的地方（§2.5）。

## 6. Blob Shadow：贴地椭圆，不是实时阴影

角色脚下一个椭圆暗斑，成本几乎为零，但**它是「角色到底站在哪」的唯一视觉线索**——
斜 45° 下没有影子，角色看起来像浮在空中，玩家会一直走不准位置。这不是装饰，是功能。

M2 最省事的做法（不需要贴图）：

1. 角色底下建一个 `Plane`（3D 对象 → Plane），命名 `Shadow`
2. `position.y = 0.01` —— **不能是 0**，和地板同高会 z-fighting（画面上一片闪烁的噪点）
3. `scale` 压成椭圆，比如 `(0.8, 1, 0.6)`
4. 材质 `M_Shadow`：`Effect` 选 `builtin-unlit`（阴影不该受光）、
   `Technique` 选 **transparent**、`Albedo` 黑色、Alpha 约 `0.3`
5. ⚠ Plane 默认是水平的（法线朝 +Y）。如果发现它立着，绕 X 转 `-90`

有贴图之后可以换成一张 64×64 的径向渐变 PNG，边缘会柔和很多。M2 不做。

## 7. 尺寸建议：通道宽度是手感的关键

按 §2.2 的规模（8m × 6m 厨房）：

| 物件 | 尺寸（米） | 说明 |
|---|---|---|
| 地板 | 8 × 6 | Plane 或 scale 成 `(8, 0.1, 6)` 的 Cube |
| 墙高 | 2.5 | 只要挡住视线边界，不用很高 |
| 工位（冰箱/烤炉/组装台） | 1.0 × 0.9 × 0.8（宽×高×深） | 一个 Cube 压一下就行 |
| 出餐口 | 1.2 × 0.9 × 0.6 | 比别的宽一点，好认 |
| 玩家半径 | **0.35** | 直径 0.7 |
| 玩家身高 | 1.6 | 胶囊 1.2 + 球头 0.4 |

> ### ⚠ 通道宽度 ≥ 1.5 米，这条最影响手感
>
> 玩家直径 0.7 米。通道留 1.0 米时，看起来「明明过得去」，
> 实际因为摇杆输入是连续方向、不是网格对齐，玩家会不停蹭到工位边缘被推开——
> **表现是「操作很黏」，但玩家不会说是通道窄，只会说这游戏手感差。**
>
> 留 1.5 米（约两倍直径）是安全值。**M2 摆位就按这个来，别等做完再改**——
> 工位一旦摆定，`logic/` 那边的坐标、单测、难度曲线都跟着定了，回头改是一串连锁修改。

摆位建议：四个工位**别摆成一条直线**。玩家在冰箱和烤炉之间来回跑是这个游戏的主要动作，
摆成一条线的话走位没有任何决策；摆成 L 形或散在四角，「先拿哪个」才有得想。

## 8. 工位怎么和 `logic/` 对齐：**尺寸只能有一个来源**

这是整份文档里最容易出 bug 的一条。

`logic/types.ts` 的 `Station` 需要 `pos` / `box`（AABB）/ `triggerRange`。
**如果编辑器里方块的尺寸和代码里的 AABB 各写一份，它们迟早会不一致**，
表现是「角色卡在看不见的墙上」或「明明贴着灶台却提示够不着」——
而且这类 bug 极难查，因为画面上一切正常。

**做法：代码从节点读尺寸，不在代码里写第二份数值。**

你在编辑器里要保证的只有三件事：

1. 工位节点命名 `Station_<名>`（`Station_Fridge` / `Station_Grill` / `Station_Assembly` / `Station_Serve`）
2. 工位的**几何中心就是节点原点** —— 别把 Cube 在子节点里偏移。
   偏移了的话节点 position 不等于方块中心，读出来的 AABB 就是错的
3. 缩放**只用节点的 `scale`**，别去改 mesh 的尺寸参数。两个地方都能改尺寸，只用一个

我这边写 `StationView` 组件读 `node.worldPosition` 和 `node.scale` 生成 `Station`。
**你摆完位置告诉我一声，我把组件写好你拖上去。**

## 9. 编辑器操作技巧

### 高频快捷键

| 键 | 作用 |
|---|---|
| `W` / `E` / `R` | 移动 / 旋转 / 缩放 |
| `F` | 聚焦到选中节点（找不到节点在哪时按这个，比手动拖视图快得多） |
| `Ctrl` + `D` | 复制节点（摆四个工位时用） |
| `Ctrl` + `Z` | 撤销 —— ⚠ **场景和资源的撤销栈是分开的**，改了材质再撤销可能撤的是场景 |

### 实用习惯

- **摆位时用顶视图**：场景视图右上角的坐标轴 gizmo 点 `Y` 轴切到俯视。
  斜视图下拖东西很难拖准，俯视图下 X/Z 一目了然
- **改的是编辑器视图，不是 Main Camera**：切视角、滚轮缩放动的都是编辑器的观察视角，
  游戏里看到的永远是 `Main Camera`。**要确认玩家看到什么，用预览（播放按钮）**
- **建好就锁**：`Main Camera`、`Floor`、两面墙都锁上（层级管理器节点右侧小锁）。
  这几样建完不再动，锁了能省掉大量误拖
- **改 Prefab 要进 Prefab 编辑模式**：双击 prefab 资源进去改，改完保存。
  在场景里直接改的是**实例**，不会同步回 prefab——这是 Cocos 最常见的「我明明改了却没生效」
- **Inspector 里数值可以拖着改**：鼠标按住字段左边的标签左右拖，比反复输入快

### ⚠ 场景文件不 merge（ROADMAP §6.5）

`.scene` 是 JSON，但**是编辑器生成的、带 uuid 的 JSON，git 冲突了没法手动合**。
所以：

- **同一时间只有一个人改场景**（这个项目里就是你）
- 我不碰 `.scene` / `.prefab` / `.meta`
- 你改场景之前 `git pull`，改完尽快 commit，别攒着

### 每次开工 30 秒

```bash
git pull
pnpm test          # 逻辑层没坏，才值得开编辑器
# → 然后再启动 Cocos Creator
```

逻辑层跑一次 1.3 秒、154 个测试。开编辑器要半分钟起。顺序反了会浪费很多时间。

## 10. 常见坑速查

| 现象 | 真因 | 修 |
|---|---|---|
| 画面一片闪烁噪点 | 两个面同高度 z-fighting | 阴影片 `y=0.01`，地板和贴片错开 |
| 方块看起来是平的、没立体感 | 光的方向和相机方向重合；或材质用了 `unlit` | 光转到 `(-50,-30,0)` 一带；材质换 `standard` |
| 角色看不见 / 找不到自己在哪 | 玩家颜色和某个工位或地板太接近 | 换成在所有背景上都跳出来的亮色 |
| 「操作很黏」，老是蹭到东西 | 通道窄于 1.5 米 | 重摆工位。**越早改越便宜** |
| 角色像浮在空中 | 没有 Blob Shadow | §6 |
| 改了 prefab 没生效 | 改的是场景里的实例 | 双击 prefab 进编辑模式改 |
| 相机莫名跑偏 | 拖别的节点时手滑拖到了相机 | 锁住 `Main Camera` |
| 构建后包体突然大了几百 KB | 挂了贴图 / 指定了 skybox cubemap / 加了物理组件 | 跑 `pnpm size` 对比，看是哪一栏涨的 |
| 编辑器里好看，真机上看不清 | 手机屏小、亮度低、还有反光 | **只信真机截图**，编辑器里的观感不作数 |
